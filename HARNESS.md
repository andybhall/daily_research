# HARNESS — Daily Dataset Hunt

You are running the Daily Dataset Hunt: a deep, autonomous search for **unclaimed
datasets** worth building research on, for the Free Systems agenda. Your job today
is to surface something genuinely new and prove it is real — not to generate a
tidy listicle. Depth and novelty are the only things that matter. A single
verified, unclaimed, high-scoring find beats fifteen plausible-sounding names.

Work through the four phases below **in order**. Do not skip phases. Do not
shortcut the verification rules. If you finish and nothing cleared the bar, say so
plainly — a null day is a valid, honest outcome and the ledger still grows via
Rejected.

---

## Anti-slop rules (non-negotiable)

These are what keep this from decaying into daily slop. Violating any of them
means the run failed, regardless of how good the memo looks.

1. **Read state first.** Before anything else, read `LEDGER.md` and `FRONTIERS.md`
   in full. A candidate that matches anything in the ledger's **Found** or
   **Rejected** sections is **dead on arrival** — do not surface it, do not
   re-litigate it. This single mechanism kills most daily-run slop.
2. **Every claim is fetched, this run.** Every assertion about a dataset's
   coverage, size, access, licensing, or update cadence must come from a page you
   fetched *during this run*, cited by its URL. **No training-data assertions.**
   If you cannot fetch a page that supports a claim, you cannot make the claim.
3. **Every candidate has a live URL, verified today.** No candidate may come from
   memory alone. Each one needs a real web search that surfaced it and a live URL
   you actually fetched and confirmed resolves this run.
4. **Unclaimed means checked.** "Unclaimed" is a claim like any other. You must run
   an actual Google Scholar (or equivalent) search for prior academic use and
   report what you found. A dataset that is already the basis of published papers
   is not unclaimed.
5. **Stay on today's frontier.** Your divergence phase must spend itself on the
   assigned frontier (see Phase 1). This prevents mode collapse onto the same five
   ideas every day.

## Phase 1 — Diverge (wide)

Spend this phase entirely on **today's frontier**. Produce **≥15 candidate
datasets** via real web searches. For each candidate:

- Run genuine searches (vary the query; think like a collector, an adversary, and a
  bureaucrat in turn). Follow leads — a good frontier has obscure corners.
- Capture a live URL and fetch it to confirm it resolves and is what you think.
- One-line what it is and why it might be behaviorally revealing.

Do not screen yet. Breadth first. Reject nothing except exact ledger collisions.
If the frontier is thin today, dig laterally (adjacent registries, the "who else
uses this data" trail, cited-by chains) rather than drifting to another frontier.

## Phase 2 — Screen

Score **every** candidate 1–5 on each of the five Willis rubric criteria (25 max):

| # | Criterion | 5 looks like |
|---|-----------|--------------|
| a | **Optimized-under-pressure / behaviorally revealed** | Data generated by people/orgs acting under real stakes, not answering a survey — revealed behavior, not stated preference. |
| b | **Incidentally accumulated / longitudinal** | A byproduct of some process, piling up over years, not assembled to be studied. |
| c | **Unclaimed** | Google Scholar search (required) shows little-to-no prior academic exploitation. |
| d | **Panel-able** | Repeated observations of the *same units* over time — supports within-unit designs. |
| e | **Maps to the agenda** | Cleanly hits Information, Representation, or Governance (name which). |

Rules:

- Show the five sub-scores and the total for each candidate in a compact table.
- **Kill anything scoring < 18/25.** Kill anything colliding with the ledger.
- For each killed candidate that was interesting enough to be worth remembering,
  note a one-line reason — these go to the ledger's **Rejected** section so we
  never re-litigate them.

## Phase 3 — Deep-dive (top 2 only)

Take the two highest-scoring survivors. For each, verify and report — every point
backed by a URL fetched this run:

1. **Access mechanics** — API? bulk download? scrape? What auth is required? What
   do the ToS and `robots.txt` actually say? Rate limits?
2. **Collection cost** — a real estimate: volume, time, storage, any paywalls or
   legal friction. Is this a weekend or a quarter?
3. **Nearest existing paper** — name the closest published work and say precisely
   why our angle differs. If you cannot find one, say what you searched.
4. **Headline figure** — sketch the one chart this dataset makes possible that
   nobody has drawn.
5. **First analysis** — the natural first question and the identification strategy
   that answers it.

## Phase 4 — Memo + commit

Write `memos/$RUN_DATE.md`, **≤800 words**, with **verified URLs mandatory** for
every factual claim. Structure:

```
# Dataset Hunt — <RUN_DATE>

**Frontier:** <n. name>
**Verdict:** <best find in one line, or "Null day — nothing cleared the bar">

## Top find: <name>
<2–3 tight paragraphs: what it is, why it is unclaimed and behaviorally revealed,
access + cost, nearest paper + our difference, headline figure, first analysis.
Every claim cited by a URL fetched this run.>

## Runner-up: <name>
<one paragraph, same discipline>

## Also screened
<compact table: candidate | score | one-line disposition>

## Ledger delta
<what was appended to Found and Rejected>
```

Then:

1. **Append to `LEDGER.md`.** Add every surviving find to **Found**
   (`name | URL | layer | status: new`) and every worth-remembering kill to
   **Rejected** (`name | URL | reason`).
2. **Emit the issue.** Write the issue title to `.hunt/issue-title.txt` (a single
   line: the best find, or `Null day — <RUN_DATE>`) and the issue body to
   `.hunt/issue-body.md` (a short triage-ready summary linking the memo). The
   workflow opens the GitHub issue from these files.
3. Leave `LEDGER.md`, the memo, and the `.hunt/` files staged; the workflow commits
   and pushes.

### If it is a null day

Say so explicitly in the memo and issue title. Still record the screened
candidates and their kill reasons in **Rejected** so the day was not wasted. Do not
pad. Do not promote a sub-18 candidate to fill space.
